# 故障排查

先在实际运行程序的主机执行：

```sh
python main.py --check
```

退出码 `0` 表示取到有效客户端数据，`1` 表示诊断或单次采集失败，`2` 表示配置/依赖错误。检查结果不会输出密码、token 或 Cookie。

## 分阶段判断

| 结果 | 判断 | 下一步 |
| --- | --- | --- |
| `stage=tcp`，连接超时 | 尚未建立管理端口连接，与 token 无关 | 核对协议、端口、路由及防火墙 |
| TCP 成功，`stage=token` 失败 | 访问了错误服务、HTTPS 证书问题，或设备不支持接口 | 检查完整管理地址、证书、JSON 字段 |
| token 可用，`stage=clients` 返回登录页/401/403 | 未认证或 SID 失效 | 配置正确管理凭据，允许程序续期 |
| 登录拒绝 | 管理用户名/密码错误，或设备限制登录 | 核对网页登录，等待锁定/退避结束 |
| `clientsData` 缺失 | 地址能通但接口、型号或权限不匹配 | 确认实际 XHR 数据接口 |
| `ok=true, device_count=0` | 服务正常，设备报告空列表 | 核对目标网络及设备关联状态 |
| `target_found=false` | 能取列表，但指定目标未匹配 | 在设备列表重新选 MAC/名称 |

## ping 成功不等于 HTTP 可用

今天部署中的问题是浏览器使用了 `http://主机:8090/#/`，程序却填成 `http://主机`。ping 仍能成功，但程序实际连接 80 端口并超时。

还要区分测试主机：电脑可能通过有线校园网访问，路由器通过另一条 WAN 路由访问，同一个 IP 的可达性不一定相同。应在安装服务的路由器上运行 `python3 /opt/router-scan/main.py --check`，不能仅用电脑上的失败替代路由器测试。

URL 的协议、端口和接口路径分别参与请求；网页地址末尾的 `#/` 不应加入管理基地址。

## token 正常但客户端接口返回 HTML

正常接口为：

```text
/?_type=loginsceneData&_tag=login_token_json
/?_type=loginData&_tag=login_entry
/?_type=vueData&_tag=vue_topo_data&Action=GetALLClients
```

token JSON 应包含 `logintoken` 和 `_sessionToken`。登录请求按设备前端协议提交密码与 token 拼接后的 SHA256，以及 `_sessionTOKEN`。取得初始 SID 不能证明已经登录；程序还会实际请求客户端 JSON 检查会话。

有些中兴页面只显示密码，前端仍发送初始化数据中的内置用户名。初始化时将用户名留空，程序读取该字段；读取不到就填写真实管理用户名，不枚举账号。

HTTP 200 可能只是登录 HTML，程序对此显示“会话未认证或已失效”，而非解析成空设备列表。正确 Cookie 在服务重启后复用；过期后重新登录。不要手动删除凭据文件来修复 token。

如果曲线停在某一时间点、日志反复显示“登录退避”，查找最近一次**非退避**错误。有缓存 SID 时，相对路径错误可能暂时被隐藏；SID 过期后，服务才发现无法读取管理凭据。OpenWrt 的 procd 服务可能以 `/` 为工作目录，即使手动在应用目录运行成功也不能证明自启续期正常。当前版本按配置目录的绝对路径读取凭据，已经覆盖这一场景。升级旧部署后应在非应用目录执行带 `--config-dir` 的预检，并重启服务。

## 部署在 OpenWrt，但要抓另一台路由器

把 `deployment.json` 的 `backend` 设为 `zte`，用 `--setup --backend zte` 设置远端完整地址和凭据。`openwrt` 只抓运行主机本身的无线接口，网页里的远端地址不参与采集。

## HTTPS 与自签名证书

HTTPS 默认验证证书。证书为其他管理地址签发或自签名时，检查结果会报告 TLS 校验失败。优先使用匹配证书的管理域名或配置正确的受信任证书；确认设备与网络可信后，可在 `deployment.json` 设置 `"tls_verify": false`，重启程序。这只影响程序的 HTTPS 请求。

OpenWrt 精简 Python 可能没有 `ssl` 模块，HTTPS 需要额外安装 `python3-openssl` 及相应证书包。若实际管理入口是 HTTP 8090，直接使用这个入口，无需为了排查而切到另一个 HTTPS 服务。

## 本机无线客户端与流量

缺少 `hostapd.*` 对象时，程序回退到 `iwinfo`。需要 `rpcd-mod-iwinfo`；采集只处理 Master/AP 接口，跳过 Client 接口。DHCP 租约不证明设备在线，因此租约存在但没有关联时不会凭租约报在线。

部分联发科驱动会在有流量时仍返回零字节计数，本机模式把这种流量显示为不可用，不据此触发假离线。中兴接口的实际流量与无线连接速率是不同字段，不能用后者代替。

## 网页/服务不可用

```sh
/etc/init.d/router-scan status
logread | grep -E '采集失败|router-scan|启动历史'
python3 /opt/router-scan/main.py --check
```

确认 `web_bind` 是当前 LAN 地址，端口没有占用。如果是 `127.0.0.1`，其他 LAN 设备不能直接访问；修改部署配置后重启。网页 `/diagnostics` 会显示当前后端、实际请求 URL、最近成功时间和错误。采集失败时设备数据带有 `stale=true`，表示上一份数据，不代表新采集证明在线。

## SSH 图形客户端能登录，脚本却失败

核对地址、端口、用户名和认证方式。图形客户端可能复用保存的密码、密钥或代理；没有出现密码输入框不等于 SSH 支持空密码。路由器服务需要有效 root 会话或等效权限。安装程序不会设置 root 密码、启用额外登录方式或保留部署密钥。
